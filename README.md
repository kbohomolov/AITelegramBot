# 🤖 Franchesco AI — Telegram IT Assistant

**Franchesco AI** — інтелектуальний Telegram-чат-бот для обробки запитів у сфері інформаційних технологій.

Бот призначений для надання коротких і зрозумілих відповідей на запитання, пов'язані з програмуванням, базами даних, API, інфраструктурою, хмарними технологіями та іншими напрямами ІТ.

Проєкт реалізований мовою **Python** із використанням фреймворку **Aiogram** та підтримує роботу з локальною базою знань і зовнішньою LLM через **OpenRouter API**.

## 🧠 Принцип роботи

Обробка користувацького запиту побудована за комбінованим принципом.

Спочатку система отримує текст запиту та перевіряє наявність відповідної інформації у локальній базі знань. Якщо відповідь знайдена, користувач отримує збережену відповідь без додаткового звернення до зовнішньої AI-моделі.

Якщо відповідної інформації у базі знань немає, запит передається до AI-сервісу через **OpenRouter API**, після чого згенерована відповідь повертається користувачу.

Спрощено процес можна представити так:

```text

│    Telegram   │
│    User       │

        │
        │ текстовий запит
        ▼
┌───────────────────────┐
│   Aiogram Bot         │
│   Query Handler       │
└───────────┬───────────┘
            │
            ▼
┌───────────────────────┐
│   Knowledge Base      │
│       MySQL            │
└───────────┬───────────┘
            │
       ┌────┴────┐
       │         │
    знайдено   не знайдено
       │         │
       ▼         ▼
┌──────────┐  ┌─────────────────┐

└────┬─────┘  └────────┬────────┘
     │                 │
     └────────┬────────┘
              ▼
       ┌──────────────┐
       │   Telegram   │
       │    User      │
       └──────────────┘
```

| ------------------------------ | -------------------------------------------------------------- |

| `locales/`                     | Локалізація українською та англійською мовами                  |

## 🛠 Технології

Основні технології та бібліотеки проєкту:

* **Python**
* **Aiogram 3.13.1** — взаємодія з Telegram Bot API;
* **SQLAlchemy 2.0.36** — ORM для роботи з базою даних;
* **MySQL** — реляційна база даних;
* **asyncmy** — асинхронний драйвер MySQL;
* **OpenRouter** — доступ до зовнішніх AI-моделей;
* **OpenAI GPT-4o-mini** — модель, яка використовується через OpenRouter у поточній реалізації;
* **Sentence Transformers** — семантичний пошук;
* **all-MiniLM-L6-v2** — модель для створення текстових embeddings;
* **Babel / Aiogram i18n** — локалізація інтерфейсу;
* **python-dotenv** — завантаження конфігурації з `.env`.

## 🗄 Структура бази даних

Проєкт використовує дві основні таблиці.

### `users`

Таблиця містить інформацію про користувачів Telegram.

| Поле                | Опис                                |
| ------------------- | ----------------------------------- |
| `id`                | Внутрішній ідентифікатор            |

| `language`          | Обрана мова інтерфейсу              |
| `is_admin`          | Ознака адміністратора               |
| `is_active`         | Статус активності облікового запису |

### `knowledge_base`

Таблиця містить структуровану базу знань.

| Поле       | Опис                 |
| ---------- | -------------------- |
| `id`       | Ідентифікатор запису |
| `question` | Питання або запит    |
| `answer`   | Відповідь            |
| `keywords` | Ключові слова        |
| `category` | Категорія інформації |

## ⚙️ Встановлення

### 1. Клонування репозиторію

```bash
git clone https://github.com/kbohomolov/AITelegramBot.git
cd AITelegramBot
```

Для роботи з поточною гілкою розробки:

```bash
git checkout develop
```

### 2. Створення віртуального середовища

```bash
python -m venv .venv
```

Активація середовища у macOS / Linux:

```bash
source .venv/bin/activate
```

У Windows:

```bash
.venv\Scripts\activate
```

### 3. Встановлення залежностей

```bash
pip install -r requirements.txt
```

## 🔐 Конфігурація

Перед запуском необхідно створити файл `.env` у кореневому каталозі проєкту.

Приклад:

```env
TOKEN=your_telegram_bot_token
DB_URL=mysql+asyncmy://username:password@localhost/database_name
OPENROUTER_API_KEY=your_openrouter_api_key
```

### Змінні середовища

| Змінна               | Призначення                |
| -------------------- | -------------------------- |
| `TOKEN`              | Токен Telegram-бота        |
| `DB_URL`             | Рядок підключення до MySQL |
| `OPENROUTER_API_KEY` | API-ключ OpenRouter        |

> **Увага:** файл `.env` не повинен публікуватися у Git-репозиторії. Не додавайте API-ключі та токени безпосередньо до вихідного коду.

## 🗄 Налаштування MySQL

Перед запуском необхідно мати доступний сервер MySQL та створену базу даних.

Наприклад:

```sql
CREATE DATABASE ai_telegram_bot;
```

Після цього необхідно вказати коректні параметри підключення у `DB_URL`.

Під час запуску застосунок ініціалізує SQLAlchemy engine та створює необхідні таблиці відповідно до ORM-моделей.

## 🔎 Семантичний пошук

У проєкті також реалізований окремий модуль семантичного пошуку:

```text
app/nlp/semantic_search.py
```

Для пошуку використовується модель:

```text
all-MiniLM-L6-v2
```

Модуль перетворює питання користувача та питання з бази знань у векторні представлення й обчислює косинусну схожість між ними.

Цей компонент призначений для пошуку найбільш семантично близької відповіді у базі знань.

> Поточний обробник повідомлень використовує прямий пошук за текстом питання через SQL `LIKE`, тоді як семантичний пошук реалізований окремим модулем і може використовуватися для подальшого розвитку системи.

## 🤖 AI-сервіс

Взаємодія з генеративною моделлю реалізована у:

```text
app/services/ai_service.py
```

Для доступу до моделі використовується **OpenRouter**.

У поточній реалізації задана модель:

```text
openai/gpt-4o-mini
```

Для AI-відповідей сформовано системний промпт, який задає такі вимоги:

* надавати чіткі та практичні відповіді;
* спочатку давати коротке визначення;
* пояснювати матеріал простою мовою;
* використовувати приклади за необхідності;
* використовувати списки, коли це покращує сприйняття;
* обмежувати відповідь приблизно 5–8 реченнями;
* правильно форматувати фрагменти програмного коду;
* відповідати мовою, обраною користувачем.

## 🔄 Логіка обробки запиту

Основна логіка обробки користувацького повідомлення реалізована у:

```text
app/handlers/user.py
```

У спрощеному вигляді алгоритм має такий вигляд:

```text
Користувач
    │
    ▼
Telegram message
    │
    ▼
Перевірка активності користувача
    │
    ▼
Пошук у KnowledgeBase
    │
    ├── Знайдено ──────► Відповідь з БД
    │
    └── Не знайдено ───► OpenRouter API
                              │
                              ▼
                         AI-відповідь
                              │
                              ▼
                         Telegram
```

Такий підхід дозволяє використовувати локальні дані для відомих запитів і залучати генеративну модель для запитів, які не представлені у локальній базі.
